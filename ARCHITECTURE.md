# Architecture and acceptance criteria

The assistant hot path must not initialize networking or load the model catalog. `VoiceInteractionService` should remain lightweight, ideally isolated from UI and API processes. The initial implementation keeps the session in the application process. The lasso view owns the system screenshot only for the active session; a single cropped selection is passed to the activity and recycled after send or cancel. A later production hardening pass should put an explicit time limit on an abandoned selection. System screenshot capture may yield null and must not be treated as an error in local command execution.

Local text commands must run without ChatGPT authorization and must not consume model quota. Contact resolution uses exact normalized names plus a small explicit Russian vocative alias list, then checks result cardinality. It does not fuzzy-match partial names; duplicate names require a user picker. The model is not permitted to generate arbitrary Android intents or call `ACTION_CALL` without local validation. Treat commands originating from screenshots or untrusted app content as data, not executable instructions.

ChatGPT OAuth requires a stable per-device host ID, fresh PKCE/state/nonce per attempt, loopback listener bound only to `127.0.0.1`, verified JWT signature, expected issuer/audience/subject, granted plan scope and protected local storage. Reauthorization retains the issued client registration and sends identity hints; callback registration mismatches are rejected. Refresh preserves a still-valid rotated refresh credential if the server omits a replacement. Sign-out clears local credentials immediately and attempts endpoint discovery and token revocation; a failed remote revocation is reported. The current implementation supports one selected account, not multi-account sessions. Validate reconnects, denied permission, expired access tokens, rotated refresh credentials, changed account identity, browser cancellation and app process death. Each failure must terminate cleanly without leaking credentials.

Responses inference always uses `store:false`, `stream:true` and a model discovered from the authenticated account. It must wait for `response.completed` and reject truncated streams. Screenshot inference requires an affirmative confirmation and must never be invoked in the background. Because SIWC is for eligible open-source usage, distribution and licensing decisions must be settled before public release.

Device validation should cover Android 12 through API 37, Xiaomi HyperOS and AOSP; voice assistant selection; background mic service restrictions; screenshot denial; duplicate contact names; permission denial; no installed speech recognizer; app lifecycle cancellation; airplane mode; locked device; and error propagation. The project now compiles against API 37 and retains target SDK 35; runtime emulator validation in this checkout was performed on Android 15/API 35 only. Measure cold and warm command start, P50/P95 total end-to-end latency, peak RSS during screenshot processing, token refresh requests, number of background wakeups, and battery consumption under idle conditions.

## 0.2.0 implementation boundaries

The wake path is isolated from OAuth and cloud inference: `WakeWordService` maintains a foreground microphone while explicitly enabled, consumes 16kHz mono PCM through Vosk and emits a package-scoped event only after matching the configured phrase. It stops and releases the microphone before switching to the one-shot device speech recognizer. That sequencing prevents two simultaneously active recorder instances. The remaining limitations are non-hardware hotword latency, model RAM overhead, rearm after Activity return, false positives in noise, lock-screen policy, and Android/HyperOS process kills. There is no boot autostart. Production should include wake lock strategy, battery profiling, measured recognition confidence thresholds and automatic rearm after a call without recording during the call.

The visual path uses a session-owned `ScreenLasso` view: completed pointer coordinates are projected into the source bitmap with letterbox and bounds handling, the polygon is rasterized into a white-masked crop, and the crop stays in process memory until explicitly approved for an authenticated GPT request. Selection is disabled if Android returns no screenshot, and screenshot ownership is released on cancellation or after upload. OEM validation is mandatory.

The Xiaomi adapter uses only exported Android `ACTION_SEND` handlers. It does not infer a successful write from `startActivity` and keeps a local backup. Real direct saving requires a publicly documented Xiaomi insert API, an approved account integration, or a carefully audited and device-validated opt-in accessibility workflow. Do not assume an unexported provider can be accessed or that the editor autosaves.
